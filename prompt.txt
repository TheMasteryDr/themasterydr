# THE MASTERY DR

## Full Personal Brand Website + Learning Management Platform

### Product, UX, UI, Architecture & Development Specification

You are building a production-quality website and digital platform for the personal brand **"The Mastery Dr."**

This is NOT a simple portfolio website.

It is a complete personal-brand ecosystem combining:

1. A premium personal brand website
2. A speaking/invitation platform
3. A reviews/testimonials platform
4. The Bereans reading community
5. Gain Mastery Institute LMS
6. Student authentication and dashboards
7. Paystack payments
8. Course management
9. Assignments and assessments
10. Certificates
11. Multiple instructor support
12. A comprehensive admin dashboard
13. Analytics
14. Email notifications
15. SEO
16. A scalable Neon PostgreSQL backend

The final product must feel like a serious global personal-development and education brand.

Do NOT create a generic "AI-generated personal portfolio website."

Do NOT use generic SaaS dashboard templates without adapting them to the brand.

Do NOT make every section look like cards floating on gradients.

The website should feel deliberately designed by a world-class digital product/design team.

# 17. COURSE PURCHASE FLOW

Selects a course.

↓

### Account

If not authenticated:

**Create Account / Login**

↓

### Email Verification

User verifies email.

↓

### Checkout

Course price is displayed.

Coupon can be entered.

↓

### Paystack

Payment initiated through Paystack.

↓

### Server-side verification

NEVER unlock a course based only on a client-side success message.

The server must verify the transaction with Paystack.

↓

### Successful verification

Create transaction record.

↓

Create enrollment.

↓

Unlock course.

↓

Send confirmation email.

↓

Student redirected to course/student dashboard.

# 45. PAYSTACK SECURITY

Never trust:

* Frontend payment success
* Client-submitted price
* Client-submitted enrollment
* Client-submitted payment status

Server must:

1. Create/initialize transaction
2. Store reference
3. Send user to Paystack
4. Receive callback/webhook
5. Verify transaction server-side
6. Confirm amount/currency/course association
7. Confirm transaction status
8. Ensure transaction hasn't already been processed
9. Record transaction
10. Create enrollment
11. Unlock course
12. Send email

Implement idempotency so duplicate webhooks cannot create duplicate enrollments.
